## 1. 프로젝트 개요 및 시스템 현황

* **시스템 명칭**: 카나다라(KANADARA) 오토캐시백 거래 승인 · 요율표 · 월별 정산 통합 플랫폼
* **주요 사용자군**:
  * **총괄 관리자 (ADMIN)**: 전체 요율표 관리, AG 발급, 전체 승인건 최종 심사 및 확정, 월별 정산 마감

* **핵심 기술 스택**:
  * **프론트엔드**: React 19, TypeScript, Vite, Tailwind CSS, Lucide React
  * **호스팅 & 서버리스**: Vercel (SPA + Serverless Functions in `api/`)
  * **데이터베이스 (Single Source of Truth)**: Google Sheets API v4 + Google Apps Script Web App
  * **버전 관리**: Git, GitHub (`main` branch)

### 결정 2: 백엔드 아키텍처 결정 (Supabase 배제 및 Google Sheets SSOT 채택)
* **결정 일자**: 2026-11-10
* **상세 내용**:
  * 외부 RDBMS/BaaS(Supabase, Firebase 등)를 별도로 신설하지 않고, **구글 스프레드시트(Google Sheets)를 단일 진실 공급원(Single Source of Truth, SSOT)이자 실시간 데이터베이스로 활용**하기로 확정.
* **배경 및 이유**:
  * 실무 관리자 및 현업 영업팀이 오토캐시백 요율표, 프로모션, 승인 내역을 엑셀 및 스프레드시트 환경에서 확인하고 즉시 수정·검토하는 업무 관행이 확고함.
  * 별도의 데이터베이스(Supabase)를 이원화할 경우, 구글 시트와 DB 간의 양방향 동기화 지연, 데이터 불일치 충돌, 추가 인프라 유지비용 및 인증 복잡도가 급격히 증가함.
* **최종 결론**:
  * 구글 시트 5대 탭(`05_요율표`, `06_프로모션`, `07_거래내역`, `08_분할결제`, `09_사용자_CM`)을 핵심 엔터티 테이블로 삼고, 웹앱은 구글 시트 API 및 Apps Script 웹훅을 통해 실시간으로 읽기/쓰기를 수행하는 경량·고효율 아키텍처 확립.

### 결정 3: '거래조건'과 '거래요율'의 명확한 차이 규명 및 데이터 분리
* **결정 일자**: 2026-11-10
* **상세 내용**:
  * 시스템 초기 혼재되어 있던 '거래조건(Condition)'과 '거래요율(Rate Table)'의 개념적·기능적 차이를 명확히 정의하고 데이터 파이프라인을 분리.
* **세부 비교 정의**:
  1. **거래조건 (Deal Condition - 정책/자격 요건)**:
     * *정의*: 카드사별 규정, 상품 자격 기준, 버전 및 적용 기간 등의 상위 '정책적 제약 조건'.
     * *속성*: 조건그룹코드(`conditionGroupCode`), 버전번호(`versionNo`), 실행일자(`effectiveFrom`), 종료일자, 카드종류(개인신용/체크), 채널(AG다이렉트 등), 선수금 규정.
     * *역할*: 해당 거래가 카드사 정책에 부합하는지 자격을 검증하는 사전 가이드라인.
  2. **거래요율 (Rate Table - 정량적 수치 계산 기준)**:
     * *정의*: 결제 시점의 카드사, 결제방법, 금액 구간, 개월수에 따라 고객 캐시백, AG 수수료, CM 수수료를 즉시 계산하는 '숫자 테이블'.
     * *속성*: 카드사, 결제방법(일시불/할부), 구분(일반/신규 등), 결제금액 구간, 할부개월수, 고객 캐시백율(%), 할부금리(%), AG 수수료율(%), CM 수수료율(%).
     * *역할*: 승인 화면에서 금액을 넣었을 때 실수령액과 수수료 금액(원)을 산출하는 직접 계산 매트릭스.
* **최종 결론**:
  * Ver 2에서는 복잡한 거래조건 검증 단계를 생략하고, 실무에서 가장 직관적인 **'거래요율(05_요율표_마스터)'** 기반의 자동 계산 체계로 전면 통합.

### 결정 5: 요율표 마스터 시트(142행) 실시간 연동 불일치 해결
* **결정 일자**: 2026-11-10
* **상세 내용**:
  * 구글 시트 `05_요율표_마스터` 탭의 전체 데이터 행(총 142행) 중 웹앱으로 96행만 불러와지고 나머지 조건이 누락되던 증상을 완벽 수정.
* **원인 분석**:
  * 기존 구글 시트 API 조회 범위가 `A1:M100`으로 하드코딩되어 100행 이후 데이터가 원천 차단되었고, TSV 파서 내부의 공백 검증 필터로 인해 유효 행 46개가 추가 누락되어 96행만 표시됨.
* **조치 및 결론**:
  * 조회 범위를 `A1:M300`으로 넉넉하게 확장.
  * 유효 데이터 검증 로직을 `카드사명(cardCompany)` 및 `결제방법(paymentMethod)` 필수 조건으로 정밀화하여 시트에 등록된 **142개 행 전체가 1건도 빠짐없이 100% 웹앱에 실시간 동기화**되도록 조치.

### 결정 6: 거래 승인건 등록 화면 UI/UX 및 카드사·할부·요율 자동화 규칙 수립
* **결정 일자**: 2026-11-10
* **상세 내용**:
  * 실무자가 거래 정보를 입력할 때 발생하는 반복 작업과 휴먼 에러를 방지하기 위해 3대 자동화 규칙 적용:
    1. **할부 개월수 선택 시 조건 요율 자동 매칭**: 할부 개월(예: 24개월) 선택 시 요율표에서 해당 개월수/금액 구간에 일치하는 캐시백율, 금리, AG/CM 수수료율 자동 입력.
    2. **요율 구분 표준화**: 불필요하게 중복 노출되던 '기본' 명칭을 제거하고, 구글 요율표 마스터와 동일하게 **'일반'**으로 단일 통일.
    3. **미등록 요율 결제방법 시각적 비활성화 (Grayed Out)**: 선택한 카드사에서 해당 결제방법(예: 다이렉트할부)의 등록된 요율이 없을 경우, 버튼을 회색으로 딤(Dim) 처리하여 실무자가 유효한 조건을 직관적으로 식별할 수 있도록 개선 (혼합 결제 모달에도 동일 적용).
* **최종 결론**:
  * AG 실무자가 수기 계산기를 두드릴 필요 없이 금액과 카드사·개월수만 클릭하면 실시간으로 정확한 정산 금액이 자동 산출되는 무결점 UI 구현.

## 6. 운영, 배포 및 유지보수 가이드 (SOP)

### 6.1 구글 시트 실시간 웹훅(Apps Script) 연동 절차
외부 Vercel 배포 환경에서 구글 시트로의 실시간 직접 쓰기를 완벽히 활성화하려면 다음 3단계를 수행합니다:

1. **Apps Script 열기 및 새 파일 추가**:
   * 구글 스프레드시트 메뉴 &rarr; **확장 프로그램 &gt; Apps Script** 진입.
   * 좌측 메뉴 **파일(+) 아이콘 &gt; [스크립트]** 클릭 &rarr; 파일명을 **`Webhook`**으로 생성.
   * *(주의: 기존 `Code.gs`는 절대 지우지 않으며, 두 스크립트가 공존하여 실행됩니다.)*
2. **코드 입력 및 저장**:
   * 생성된 `Webhook.gs`에 웹앱 설정 화면의 **[코드 원클릭 복사]** 코드(`doPost` / `doGet`)를 붙여넣고 저장(`Ctrl+S`).
3. **웹 앱 배포 및 URL 등록**:
   * 우측 상단 **[배포] &gt; [새 배포]** 클릭.
   * 유형: **웹 앱(Web App)** 선택.
   * 액세스 권한: 반드시 **모든 사용자(Anyone)** 선택 후 **[배포]** 클릭.
   * 생성된 웹 앱 URL(`https://script.google.com/macros/s/.../exec`)을 복사하여 웹앱 **[설정(SettingsPageV2)]** 하단 웹훅 URL 입력란에 붙여넣고 **[저장 및 시트 즉시 전송]** 클릭.
